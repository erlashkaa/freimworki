# REST API FinanceTracker

Базовый адрес локального сервера: `http://127.0.0.1:8765`.
Все изменяющие запросы отправляют `Content-Type: application/json`.
Ответы — JSON. Суммы возвращаются строками с двумя знаками после запятой.
Даты — `YYYY-MM-DD`, месяцы — `YYYY-MM`.

## Сессии и защита запросов

1. Выполнить `GET /api/session/`, сохранить cookies и поле `csrfToken`.
2. Передавать `X-CSRFToken` и cookies в POST/PATCH, включая вход и регистрацию.
3. После входа/регистрации использовать новый `csrfToken` из ответа.
4. Сессия хранится в HttpOnly cookie, её срок — 8 часов.

| Метод | Адрес | Назначение и тело |
|---|---|---|
| GET | `/api/session/` | `{user: {username} или null, csrfToken}` |
| POST | `/api/register/` | `{username, password1, password2}`; 201 и новая сессия |
| POST | `/api/login/` | `{username, password}`; 200 и новая сессия |
| POST | `/api/logout/` | `{}`; завершение текущей сессии |
| GET | `/api/categories/` | `{results: [{id, name, limit}]}` |
| POST | `/api/categories/` | `{name, limit}`; limit может быть null; 201 |
| PATCH | `/api/categories/{id}/` | Любое из полей name, limit; 200 |
| GET | `/api/transactions/` | Список операций с фильтрами и пагинацией |
| POST | `/api/transactions/` | Создать операцию; 201 |
| POST | `/api/transactions/{id}/cancel/` | `{}`; отменить, 200; повтор безопасен |
| GET | `/api/summary/` | Баланс за всё время и сводка за месяц |
| GET | `/health/` | Проверка процесса: `{status: "ok"}` |

Все финансовые адреса требуют входа. Пользователь видит и меняет только
свои категории и связанные с ними операции. Права проверяются сервером.

## Регистрация

Имя: до 150 символов, правила стандартного пользователя Django.
Пароль: минимум 10 символов, два совпадающих ввода, проверки сходства с
именем, распространённых и полностью цифровых паролей. На один IP разрешено
30 попыток входа и 10 регистраций за 5 минут (включая успешные запросы).
После превышения лимита сервер отвечает 429.

## Категории и бизнес-правила

Название категории: 1–80 символов после удаления пробелов по краям,
уникально для пользователя, регистр учитывается.
Лимит: null или от 0 до 9999999999.99, максимум два десятичных знака.
Превышение лимита не блокирует запись фактически совершённой покупки:
отрицательное remaining отображается в интерфейсе как превышение.

## Создание операции

```json
{
  "category": 1,
  "amount": "1200.50",
  "type": "expense",
  "date": "2026-10-18",
  "description": "Покупки"
}
```

category — ID своей категории. amount — положительное конечное число,
не более 9999999999.99 и двух знаков после запятой. type — income или expense.
description необязателен, до 300 символов. date — существующая календарная
дата. Сервер самостоятельно создаёт ID и устанавливает is_cancelled=false;
переданные клиентом owner/id/is_cancelled не используются.

Ответ содержит id, category, category_name, amount, type, date, description,
is_cancelled. Отмена сохраняет запись в истории и исключает её из расчётов.

## История

`GET /api/transactions/?month=2026-10&category=1&ordering=-amount&page=1`

Параметры необязательны. Без month возвращается история за всё время.
ordering: date, -date (по умолчанию), amount, -amount.
page: целое от 1 до 100000. Размер страницы — 20.

```json
{"results": [], "count": 0, "page": 1, "page_size": 20}
```

## Сводка

`GET /api/summary/?month=2026-10`. Без параметра — текущий месяц Москвы.

```json
{
  "balance": "5000.00",
  "month": "2026-10",
  "income": "6000.00",
  "expense": "1000.00",
  "categories": [
    {"id": 1, "name": "Продукты", "limit": "3000.00",
     "spent": "1000.00", "remaining": "2000.00"}
  ]
}
```

balance учитывает все активные операции. income, expense и spent относятся
к выбранному месяцу. При отсутствии лимита limit и remaining равны null.
Сводка кэшируется на 60 секунд с отдельным ключом пользователя, месяца
и версии данных. Изменения через API и импорт немедленно меняют версию.

## Ошибки

```json
{"error": "Проверьте введенные данные", "fields": {"amount": ["Ошибка"]}}
```

400 — некорректные данные/JSON; 401 — нет сессии или неверный пароль;
403 — ошибка CSRF; 404 — объект отсутствует или принадлежит другому;
405 — неверный HTTP-метод; 409 — повтор названия; 415 — неверный Content-Type;
429 — ограничение попыток. Ошибки Django/WSGI вне обработчиков API
(например, слишком большой запрос) могут иметь HTML/text-тело;
интерфейс обрабатывает такой ответ общим сообщением.
