# Запуск и защита проекта в VS Code

## Результат проверки

Требования ПР5 и ПР6 к реализации совпадают. Веб-версия содержит сервер
Django, REST API, интерфейс HTML/CSS/JavaScript, аккаунты с раздельными
данными, защиту запросов, кэширование, тесты и локальное развёртывание.

Публичный сервер и HTTPS-домен не подключены. Если преподаватель требует
ссылку, доступную через интернет, это отдельный оставшийся шаг.
Отчёты Word по ПР5 и ПР6 пока не составлены; существующий Word относится к ПР3.
Актуальная версия ПР5–6 находится в ветке master репозитория
https://github.com/erlashkaa/freimworki. В прежнем архиве проекта
веб-версии может не быть.

## 1 Открыть правильную папку

В VS Code выбрать File → Open Folder и открыть:

```text
C:\Users\gabdu\OneDrive\Рабочий стол\univer\freimworki
```

В проводнике VS Code должны быть `manage.py`, `serve.py`, `finance/`,
`webconfig/`, `requirements.txt`. Если их нет, открыта старая копия,
например FinanceTracker, распакованная из предыдущего архива.

Открыть Terminal → New Terminal. Команды ниже предназначены для PowerShell
и выполняются из корневой папки проекта. Терминал оставить открытым.

## 2 Первый запуск на новом компьютере

Проверить Python:

```powershell
python --version
```

Требуется Python 3.10 или новее. Если команда python не найдена, попробовать
`py --version` и использовать `py -m venv .venv` для создания окружения.

Если папки .venv ещё нет:

```powershell
python -m venv .venv
```

Затем выполнить по очереди, дожидаясь завершения каждой команды:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py collectstatic --noinput
.\.venv\Scripts\python.exe serve.py
```

Активация окружения не требуется: используется полный путь к его Python.
На уже подготовленном компьютере достаточно последней команды.
В VS Code при наличии расширения Python можно выбрать через Ctrl+Shift+P →
Python: Select Interpreter → `.venv\Scripts\python.exe`.

Открыть в Chrome или Edge адрес http://127.0.0.1:8765/.
Занятый сервером терминал — нормальное поведение. Остановка: Ctrl+C.
После остановки страницы не смогут получать и сохранять данные.

## 3 Демонстрация приложения за 5 минут

Для предсказуемых цифр создать новый аккаунт, например с уникальным именем
для защиты. Придумать собственный пароль от 10 символов, не похожий на логин.
Все демонстрационные операции вводить датой текущего выбранного месяца.

1. Создать категории «Зарплата» без лимита и «Продукты» с лимитом 5000.
2. Добавить доход 30000 в категорию «Зарплата».
3. Добавить расход 1200 в категорию «Продукты».
4. Показать: баланс 28800, доходы 30000, расходы 1200,
   остаток лимита продуктов 3800.
5. Добавить ещё расход 4000 на продукты. Показать: баланс 24800,
   расходы 5200, превышение лимита 200.
6. Отменить расход 4000. Строка останется со статусом «Отменена»,
   баланс вернётся к 28800, расходы — к 1200, остаток лимита — к 3800.
7. Поменять сортировку истории и фильтр категории. Выбрать другой месяц:
   его история/сводка изменятся, общий баланс за всё время останется прежним.
8. Перезагрузить страницу и показать сохранность данных.
9. Выйти, создать второй аккаунт: его история и категории пустые.
10. Войти в первый аккаунт: прежние данные доступны снова.

Фраза для объяснения:

> FinanceTracker — приложение учёта личных доходов и расходов. Сервер
> реализован на Django, данные хранятся в SQLite, клиент использует JavaScript
> и fetch. У каждого пользователя свои категории и операции. Лимиты показывают
> превышение бюджета, но не запрещают записывать фактически сделанные покупки.

## 4 Показать API

В браузере открыть F12 → Network → Fetch/XHR. Добавить операцию или изменить
фильтр. Выбрать запрос к `/api/transactions/` или `/api/summary/`.
Показать Headers, Payload и Response: метод запроса, отправленные данные,
ответ JSON. Пароли и содержимое cookies демонстрировать не нужно.

После входа можно открыть в отдельной вкладке:

```text
http://127.0.0.1:8765/api/categories/
http://127.0.0.1:8765/api/transactions/
http://127.0.0.1:8765/api/summary/
```

Фраза для объяснения:

> Браузер отправляет JSON-запросы к REST API. Сервер проверяет сессию,
> права и поля, сохраняет данные и возвращает JSON. Интерфейс обновляется
> без полной перезагрузки страницы.

## 5 Какие файлы показать в VS Code

| Тема | Файл | Что объяснить |
|---|---|---|
| Стек и настройки | webconfig/settings.py | SQLite, сессии, middleware, кэш |
| Модели | finance/models.py | Category, Transaction, связь категории с пользователем |
| Проверка данных | finance/forms.py | Положительная сумма, дата, своя категория |
| API | finance/urls.py и finance/views.py | Маршруты, методы, создание, отмена |
| Права доступа | finance/views.py | Фильтрация по request.user; чужие объекты недоступны |
| Расчёты и кэш | finance/services.py | Баланс, месячные расходы, версия кэша |
| Интерфейс | finance/templates/finance/index.html | Формы, сводка, таблица |
| Обращения к серверу | finance/static/finance/app.js | fetch, CSRF, обработка ответов |
| Оформление | finance/static/finance/app.css | Стили и адаптация к узкому экрану |
| Безопасность | finance/middleware.py | CSP и запрет браузерного кэша личных ответов |
| Тесты | tests/test_web.py | Сессии, CSRF, чужие данные, баланс и кэш |
| Импорт | tests/test_import_json.py | Восстановление связей и откат при ошибке |
| Развёртывание | serve.py | Waitress, четыре потока, localhost |
| Контракт API | docs/API.md | Адреса, поля, статусы и примеры |

Полезные пояснения:

- Аутентификация — проверка, кто вошёл. Авторизация — какие данные ему доступны.
- Пароли хранятся как хэши. CSRF защищает изменяющие запросы.
- Пользовательские строки выводятся через textContent. Запросы к БД идут через ORM.
- Кэш сводки хранится 60 секунд. Ключ содержит пользователя, месяц и версию
  данных. Изменение категории/операции меняет версию.
- Тест подтверждает 5 запросов к БД при первом расчёте сводки и 1 при повторном.
- История разбита по 20 строк; select_related загружает категории без
  дополнительного SQL-запроса для каждой операции.

Для ПР5 удобно показать сервер, API и интерфейс; для ПР6 — безопасность,
кэш, тестирование и развёртывание. Это удобный порядок защиты, а не отдельные
разные требования документов.

## 6 Показать тесты во втором терминале

Нажать «+» в панели Terminal VS Code. Первый терминал с сервером не закрывать.

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --basetemp=.test-tmp-demo
.\.venv\Scripts\python.exe -m flake8 --jobs=1 .
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
```

Ожидается: 45 passed; flake8 без вывода; проверка Django без замечаний;
No changes detected для миграций. Тесты используют отдельную тестовую БД.
На данном компьютере полный прогон занимает около одной–полутора минут.

Для нагрузки сервер должен продолжать работать:

```powershell
.\.venv\Scripts\python.exe scripts/load_test.py --requests 200 --workers 8 --output build/load-test-demo.json
```

Показать requests=200, workers=8, errors=0 и время ответа.
Скрипт создаёт отдельный тестовый аккаунт и 20 операций, затем параллельно
запрашивает сводку и историю. Времена зависят от компьютера. Это проверка
данного сценария, а не доказательство готовности к высокой публичной нагрузке.

## 7 Частые проблемы

- **Нет .venv\Scripts\python.exe**: проверить папку и создать окружение.
- **Нет Django/Waitress**: выполнить установку requirements.txt именно через .venv.
- **no such table**: выполнить `manage.py migrate`.
- **Порт занят**: открыть уже работающий сервер либо запустить
  `serve.py --port 8766` и открыть http://127.0.0.1:8766/.
  Для нагрузочного теста тогда передать `--url http://127.0.0.1:8766`.
- **Нет оформления или видны старые стили**: выполнить collectstatic,
  перезапустить сервер и нажать Ctrl+F5 в браузере.
- **Терминал не принимает новую команду**: сервер занимает его; открыть второй
  терминал или остановить сервер Ctrl+C.
- **Git показывает (END)**: нажать Q в английской раскладке.
- **Запросы на вход отклоняются с 429**: подождать 5 минут, ограничение сработало
  после большого количества попыток с одного IP.

`main.py` запускает прежний CLI, `gui.py` — прежнее окно Tkinter.
Для ПР5–6 запускать `serve.py`. Старые версии используют JSON,
веб-версия — SQLite; это два разных хранилища.
